# 工作总结系统设计

## 目标
打造一个覆盖日、周、年度总结的统一平台，帮助员工及时记录成果、反思问题，管理层能实时掌握团队运行状态，并在年底快速生成绩效依据。

## 核心功能
1. **日总结**
   - 智能模板（任务完成情况、阻碍、明日计划）。
   - 与项目管理系统（如Jira、Tapd）同步当日任务。
   - 支持语音/移动端输入，自动打标签。
2. **周总结**
   - 自动汇总本周日总结亮点、问题，生成初稿。
   - 添加跨项目协作、风险、资源诉求等字段。
   - 结合周目标完成度生成可视化报告。
3. **年度总结**
   - 以周总结为基础，按季度聚合成年度大事记。
   - 智能提炼KPI指标、关键成果，支持附件证明材料。
   - 输出可导出PDF/Slides模板，便于述职。
4. **通知与审批流**
   - 钉钉/企业微信提醒未提交人员。
   - 支持部门负责人批注、追踪整改。
5. **数据分析**
   - 完成率、响应时效、风险分布等仪表盘。
   - 支持自定义维度（项目、产品线、地区等）。

## 系统架构
```
前端 (Web + 小程序)
  |
API Gateway (GraphQL/REST)
  |
微服务：
  - Summary Service（日/周/年逻辑）
  - Report Service（自动汇总、导出）
  - Notification Service（消息推送）
  - Auth & Org Service（组织架构、权限）
  |
事件总线 (Kafka) & 任务队列 (Redis/Sidekiq)
  |
数据库：PostgreSQL（结构化数据）、Elasticsearch（全文搜索）、对象存储（附件）
```

## 数据模型示例
### 日总结 `daily_entries`
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 主键 |
| user_id | UUID | 员工 |
| date | Date | 日期 |
| tasks | JSONB | 完成事项列表 |
| blockers | TEXT | 阻碍 |
| plan | TEXT | 明日计划 |
| tags | TEXT[] | 自动标签 |

### 周总结 `weekly_reports`
| 字段 | 类型 | 说明 |
| id | UUID | 主键 |
| week_start | Date | 周起始 |
| highlights | TEXT | 亮点 |
| issues | TEXT | 问题 |
| requests | TEXT | 资源诉求 |
| auto_summary_ref | UUID | 自动汇总任务ID |

### 年度总结 `annual_reviews`
| 字段 | 类型 | 说明 |
| id | UUID | 主键 |
| year | INT | 年份 |
| achievements | TEXT | 关键成果 |
| kpi | JSONB | KPI 指标 |
| attachments | JSONB | 证明材料链接 |

## 关键流程
1. **每日提醒**：工作日9:00推送昨日总结回顾，17:30推送今日总结填写提醒。
2. **自动周报**：每周五晚触发ETL，把当周日总结聚合生成草稿，用户只需补充额外信息。
3. **年度报告**：12月初生成年度数据包，员工编辑完善后交由主管批阅。
4. **审批与反馈**：主管可在线批注，系统自动记录整改项并纳入下周总结。

## 权限与安全
- 单点登录（SSO）对接企业身份系统。
- 细粒度权限：个人、直属上级、HR、管理员。
- 数据加密存储，操作日志可审计。

## 上线规划
1. **MVP（1个月）**：日总结+提醒+基础报表。
2. **迭代1（2个月）**：周总结自动化、导出能力、权限细化。
3. **迭代2（4个月）**：年度总结、数据分析大屏、AI智能分析。

## 成功指标
- 日总结提交率 ≥ 90%
- 周总结自动生成节省时间 ≥ 50%
- 年度总结准备时间从2周缩短至3天
- 管理层满意度 ≥ 4.5/5
